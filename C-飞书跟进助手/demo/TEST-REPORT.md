## 真实服务/飞书九项检查

1. 载入原项目中英文 WhatsApp 文本，生成 3 条诉求、2 条顾虑、3 条待办摘录；确认前客户档案不变，重复确认只追加一次。
2. 修改采购预计日期到演示当天后第 5 天；计算延迟 14 天，等级红，提示可能影响“主梁组焊”。
3. 录入虚构回款风险，选择橙色并确认；重复确认不生成重复风险。
4. 连续扫描节点第二次新增提醒为 0。
5. 月报手算核验：45 总数、15 成交、27 丢单、3 暂停、成单率 35.7%。
6. 已有样例评测 14/14。
7. 飞书四表写入与逐字段读回：客户 12、节点 13、风险 4、成交/丢单 85。
8. 再次同步飞书，记录数量不变，同本地 ID 更新原记录。
9. 创建飞书月报并读回，确认 35.7、45、27 等统计数字存在于实际文档中。

## 测试中发现并修复

- CLI `record-upsert` 实际返回 `record.record_id_list`；表列表使用 `id`。按真实返回结构处理，改为批量写入与按本地 ID 读回索引，支持重试恢复。
- 飞书写后立即读偶尔为旧版本；加入最多 5 次有限重读，字段持续不一致仍报失败。
- 自动登记的红色风险原先不会随节点日期变动更新描述；现已更新依据与等级，节点完成时关闭对应自动风险。
- 同等级提醒在先升级再降级时可能重复；现保留每等级的 24h 发送记录。
- 客户“Please send”原先会错误地把客户视为待办负责人；现不从请求句指派负责人，保留人工确认提示。
- 摘要页重绘后项目选择可能回到首项；现保留当前摘要对应项目。

## 不作为已验证的能力

- 真实浏览器视觉、手机布局、上传文件对话框。
- 大模型理解质量、召回率/准确率目标、复杂中文与英文语义、EML 的 MIME 附件解析。
- 飞书群 @、事件订阅、交互卡片、群定时推送、机器人身份收发、真实部门与负责人绑定。
- 语音、生产环境权限与多用户角色、A/B 真正服务间接口、真实 CRM 或客户数据。
