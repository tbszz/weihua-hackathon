# 飞书跟进助手 P0 MVP 实现与验收

目标：基于现有 PRD、样例数据和工作台品牌，实现可在浏览器操作、可持久化、能真实写入飞书的最小演示。

架构：Node.js 22 原生 HTTP 服务 + 原生 HTML/CSS/JS 前端；JSON 原子落盘，隔离于 data/runtime；飞书经本机 lark-cli 子进程参数数组调用，凭证不复制到项目。平台底座目前只有设计，保留适配边界，不伪造底座实现。

选择：纯静态演示无法验证回填，完整 CRM 超出场景；采用本地轻量服务和飞书镜像四张表。浏览器为演示与审批工作台，飞书为真实导出目标。群内事件订阅、语音和云端模型作为明确后续项。

设计：卫华红 #D7000F、深墨 #1F2329、浅灰 #F5F6F7、白 #FFFFFF、蓝 #2B7DE9；Segoe UI/Microsoft YaHei 正文，Consolas 数字。左侧功能导航，中央工作区，摘要审批右栏。独特要素为带证据行号的沟通摘录与风险节点时间线。复用 ../weihua-ai-workbench/colors_and_type.css 品牌值，不修改相邻项目。

实施顺序：
1. 先建立规则验收用例：采购 0/3/4/7/8 天、投标逾期、无日期、完成、分类信息不足、报告分母。
2. 实现 domain、相对日期种子、JSON 存储、摘要/风险草稿确认与幂等、节点编辑、月报和上游导入。
3. 实现 lark-cli 适配器：状态检测、建立四表、记录 upsert、月报文档。只处理本 Demo 的空间。
4. 实现浏览器：总览、沟通摘要、节点风险、文字风险登记、月报、飞书连接与运行记录。
5. 运行自动化 API/规则测试，启动服务，浏览器手动操作闭环，真实飞书导出后读回核验。
6. 留下运行方法、逐项交付边界与手测记录。

验收：未确认不回填；重复确认无重复；规则边界符合 PRD；重启数据仍在；飞书 API 失败明确呈现且不标成功；月报数字等于当月数据；中文与英文样例均可提取原句，缺失负责人/绝对日期不猜测。
