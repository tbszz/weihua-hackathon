# 报价智能体竞品分析

> 版本 v0.1｜2026-11-07  
> 结论基于公开官网与公开资料调研，主要用于产品定位、答辩差异化与后续功能取舍。供应商宣传的效率数字未做独立验证。

## 1. 核心结论

1. **“AI 读取客户技术协议 / 招标文件并输出合规矩阵、偏离表”已经有直接竞品**，代表产品包括 Tender Answer、OdysseyGPT、Tendrio、Operaide。它们与我们最接近的能力是：逐条抽取需求、比对内部产品资料、输出符合/偏离/待澄清状态、给工程师复核。
2. **传统 CPQ 的主航道仍是“从己方产品配置出发算价”**，代表产品包括 Tacton、Salesforce Revenue Cloud/CPQ、Cincom、camos、Configure One、未蓝云、金蝶 CPQ。它们的强项是规则配置、价格治理、审批、ERP/CRM 集成，但通常不把“客户几十页技术协议”作为第一输入。
3. **我们的产品不能把“AI 读协议”“输出偏离表”“带出处”讲成独有卖点**。这些已经是条款合规类产品的标配。真正可防守的差异是：
   - 面向起重机/卫华场景的配套件、型号、参数、商务风险规则；
   - 大模型只提供线索，确定性规则引擎兜底，模型不能把结论改得更宽松；
   - 报价员每次改判自动沉淀为审核后的知识条目、SOP，并可申请固化为规则；
   - 与现有售前软件形成“客户协议审查 → 需求参数表 → 售前配置报价”的上游衔接；
   - 面向内部敏感协议的脱敏与本地模型模式。
4. **最危险的竞品不是通用 CPQ，而是 Tender Answer / OdysseyGPT / Tendrio 这类条款审查产品**。如果它们进入中国市场并完成中文招标语料、行业规则和本地化部署，会直接挤压本项目通用能力部分。
5. **答辩口径建议**：不要说“别人都不能读协议”，应说“通用条款审查已经出现，但卫华场景赢在行业规则、内部知识闭环和与售前软件的衔接”。

## 2. 竞品分层

| 层级 | 代表产品 | 输入 | 核心输出 | 与本项目关系 |
|---|---|---|---|---|
| 条款合规 / 招标响应 | Tender Answer、OdysseyGPT、Tendrio、Operaide、inviqon | 客户招标书、技术规格、RFQ、图纸、附件 | 需求清单、合规矩阵、偏离与澄清表、工程师问题 | **最直接竞品** |
| AI RFQ 到报价智能体 | Marbell、Mavlon、opAIda、Axle、SalesCycle | 邮件、PDF、Excel、图纸、BOM | 成本树、配置、BOM、价格、审批稿 | 覆盖报价后段，与本项目部分重叠 |
| 制造业 CPQ | Tacton、Salesforce、Cincom、camos、Configure One | 销售选择的型号/参数/选项 | 可售配置、价格、报价单、审批、BOM/订单 | 现有售前软件同类，需衔接而非替代 |
| 国内工业 CPQ / 报价系统 | 未蓝云、金蝶 CPQ、梅施、Q-SMART、青翼 | 参数选型、BOM、成本项、报价策略 | 成本核算、定价、报价单、审批、系统集成 | 中文与本土 ERP 生态强，但协议审查弱 |
| 零件 / 图纸报价 | AMFG、链曼斯 PQA、Uptool | CAD、图纸、工艺、零件清单 | 工时、工艺路线、成本、零件报价 | 解决零件/工艺，不是整机技术协议审查 |
| 卫华现有售前软件 | 内部系统 | 己方型号、参数、配置 | 己方技术协议、配置、报价 | 本项目应做其上游输入与人工复核层 |

## 3. 重点竞品拆解

### 3.1 Tender Answer

- **定位**：面向工业招标的逐条技术响应。
- **能力**：读取招标文件，拆成需求；比对产品文档、标准与历史投标；输出合规矩阵、偏离表、技术响应草稿、工程师问题清单。
- **优势**：
  - 输出物非常贴近投标交付：合规矩阵 + 偏离表 + 技术响应草稿；
  - 每个“符合”都链接到数据表页、测试证书或过往投标证据；
  - 对“部分满足 / 需工程师判断”有明确分流。
- **弱项 / 机会**：
  - 公开资料偏阀门、泵、执行器等流程设备，未看到起重机配套件与中文招标语境的深度规则；
  - 更偏“响应招标”，本项目还覆盖报价前非标成本点、模糊项、商务风险与内部报价知识沉淀；
  - 未强调“改判自动变成知识条目 → SOP → 规则”的闭环。
- **来源**：[Tender Answer](https://tenderanswer.com/)

### 3.2 OdysseyGPT

- **定位**：面向阀门、泵、执行器、仪表制造商的技术规格审查。
- **能力**：读取完整 tender/RFQ 包，逐条给状态、客户文档出处、己方文档引用、复核决定，输出合规矩阵与 Deviations & Clarifications。
- **优势**：
  - 每行都有“客户文档出处 + 己方文档引用 + 复核人决定”，治理思路成熟；
  - 除合规矩阵外，还有客户规格审查、数据表比较、偏差登记、内部待办表；
  - 明确区分对外交付清单和内部待办清单。
- **弱项 / 机会**：
  - 行业模板偏流程设备，不覆盖起重机型号、跨度、工作级别、蒲瑞配套件等规则；
  - 对“报价思路/加价点”的沉淀不如本项目直接；
  - 中文本地部署、内部售前软件衔接、飞书流程不在公开卖点中心。
- **来源**：[OdysseyGPT](https://odysseygpt.ai/product)

### 3.3 Tendrio

- **定位**：工业制造商的 AI 招标评估。
- **能力**：把复杂 RFQ / tender 与产品资料、能力文档比对，输出符合、部分满足、缺口、需专家复核的矩阵。
- **优势**：
  - 强调投标前决策：是否投标、澄清、重新报价或放弃；
  - 覆盖产品规格、质量证书、手册、测试报告、服务说明、能力文档；
  - 把工程、采购、认证、交付例外作为风险项识别。
- **弱项 / 机会**：
  - 更偏“能不能接、差在哪里”的评估，不是完整的报价知识运营系统；
  - 未看到面向中文技术协议和起重机行业词表的专门能力；
  - 缺少从报价员改判到 SOP 导出的闭环。
- **来源**：[Tendrio](https://industry.tendrio.ai/)

### 3.4 Operaide

- **定位**：机械与工厂工程领域的 specification-to-quote。
- **能力**：读取客户规格、需求清单、招标文件；逐条匹配设备、选项和价格；标记偏离；由销售工程师复核毛利与交期。
- **优势**：
  - 直接覆盖“规格 → 机器/选项 → 价格 → 偏离”的完整链路；
  - 每个需求带页码，明确“每条需求都被列出”；
  - 销售工程师最终决定偏离，符合人机协作治理。
- **弱项 / 机会**：
  - 追求直接生成报价，本项目刻意不做最终算价，避免与售前软件冲突；
  - 未突出本地模型、协议脱敏、规则引擎防越权；
  - 起重机配套件知识、历史报价与内部通知版本管理需要行业化落地。
- **来源**：[Operaide](https://www.operaide.ai/solutions/industries/mechanical-engineering/specification-to-quote)

### 3.5 Marbell / Mavlon / opAIda：AI RFQ 到报价

- **共同能力**：读取邮件、PDF、规格书、图纸、BOM，抽取结构与参数，结合库存、成本、历史、毛利规则，生成可审批报价。
- **优势**：
  - Marbell 强调每行报价能回溯客户请求页，工程版本变更后相关报价自动重跑；
  - Mavlon 明确定位“从客户投标包出价，而不是从产品目录选配”，非常贴近非标设备；
  - opAIda 强调从邮件、PDF、图纸、表格到人工审批的闭环。
- **弱项 / 机会**：
  - 这些产品多数默认接入企业 ERP/CPQ/PLM，实施周期和数据治理要求高；
  - 对中文起重机行业术语、卫华内部标准、蒲瑞配套件规则需要重新建模；
  - 本项目可以先用“轻量上游审查 + 导出参数表”切入，不必等待全部系统打通。
- **来源**：[Marbell](https://marbell.com/solutions/quote-desk/)、[Mavlon](https://mavlon.co/manufacturing-quoting-software)、[opAIda](https://opaida.ai/zh/solutions/ai-cpq)

### 3.6 Tacton

- **定位**：复杂制造业 CPQ 与配置生命周期管理。
- **能力**：约束式配置、引导销售、动态定价、可视化配置、报价文档，AI 辅助建模。
- **优势**：
  - 配置规则和工程约束成熟，强调“生成式 AI 靠近答案，配置真相给出正确答案”；
  - 能连接 CRM、ERP、PLM、CAD、PIM 等；
  - AI Modeling Assistant 可把产品资料转成 CPQ 模型草稿，专家审核后同步。
- **弱项 / 机会**：
  - 主输入是己方可配置产品目录，不是任意客户协议；
  - 面向完整 CPQ 实施，较重；
  - 不解决“报价员每次改判沉淀经验”的组织知识问题。
- **来源**：[Tacton CPQ](https://www.tacton.com/buyer-engagement-platform/)、[Tacton AI](https://www.tacton.com/buyer-engagement-platform/artificial-intelligence/)

### 3.7 Salesforce Revenue Cloud / CPQ

- **定位**：通用收入与报价流程平台。
- **能力**：AI agent 辅助配置、定价、报价、审批和续约；底层由产品兼容、价格、折扣、合同等确定性流程约束。
- **优势**：
  - 对“AI 建议 + 确定性规则 + 审批”的治理表达很成熟；
  - 与 CRM、合同、计费、审批天然打通；
  - 适合已有 Salesforce 生态的企业。
- **弱项 / 机会**：
  - 通用性强，但制造业深度约束和行业图纸/配套件能力常需补充；
  - 对中文招标协议和本地私有化场景不如国内厂商直接；
  - 不天然沉淀报价工程师的条款判断经验。
- **来源**：[Salesforce CPQ](https://www.salesforce.com/sales/cpq/what-is-cpq/)

### 3.8 国内工业 CPQ / 智能报价

#### 未蓝云 AI+CPQ

- **能力**：3D 配置、规则校验、BOM 级成本、AI 推荐价格、30 秒报价、审批和系统集成。
- **优势**：覆盖 CTO、ETO、EPC；中文产品表达完整；面向工业场景。
- **弱项**：公开重点仍是从配置和成本模型出价，而非客户协议非标条款审查。
- **来源**：[未蓝云](https://www.futrblue.com/)

#### 金蝶 CPQ 配置报价助手

- **能力**：解析客户需求，匹配客户/物料/BOM，校验配置约束，调用 ERP 定价，生成报价单。
- **优势**：与金蝶 ERP 生态和国内企业管理流程结合紧密；强调一致性、折扣与毛利合规。
- **弱项**：公开描述以结构化需求与 BOM 配置为主，协议原文高亮、条款证据链和知识沉淀不是中心。
- **来源**：[金蝶 CPQ 配置报价助手](https://www.kingdee.com/resources/ai-agent/1532695327785912129)

#### 梅施 CPQ / Q-SMART / 青翼 CPQ

- **共同能力**：产品配置、成本核算、定价策略、审批、版本追踪、ERP/CRM 集成。
- **优势**：熟悉国内非标制造、项目型销售、成本敏感行业；支持多客户等级、多场景定价和审批。
- **弱项**：通常假设需求已被结构化；对客户协议里的模糊、不满足、可偏离和商务罚则缺少专门治理。
- **来源**：[梅施 CPQ](https://www.msebc.com/products/cpq)、[Q-SMART](https://www.jgdt.com/Product/detail/97)、[青翼 CPQ](https://app.qy-cloud.cn/articles/3ee216fb-0da2-4709-8fc7-6e3750a93376?locale=zh-CN)

### 3.10 零件 / 工艺报价类

#### 链曼斯 PQA

- **能力**：图纸识别、工艺路线、工时演算、项目报价、内部成本核算、外协核价；人工复核记录进入学习。
- **优势**：工艺知识强，强调特征识别、规则为主、AI 为辅、人工审核和追溯。
- **弱项**：面向零件/工艺，不处理整机技术协议、商务条款和售前软件衔接。
- **来源**：[链曼斯 PQA](https://linkmes.com.cn/product-quotation.html)

#### AMFG / Uptool / SalesCycle

- **能力**：从 CAD、图纸、BOM、邮件、RFQ 生成工时、成本、报价或结构化需求。
- **优势**：零件报价、制造估算、历史相似件检索和成本树解释成熟。
- **弱项**：主要解决制造过程与零件成本，不是起重机整机技术协议的非标与风险审查。
- **来源**：[AMFG](https://www.amfg.ai/estimating-and-quoting)、[Uptool](https://uptool.com/)、[SalesCycle](https://www.salescycle.ai/ai-solutions/quotation-management/)

## 5. 竞争威胁排序

| 排名 | 威胁 | 原因 | 应对 |
|---|---|---|---|
| 1 | Tender Answer / OdysseyGPT / Tendrio | 产品形态最接近，已具备逐条审查、偏离表、出处和工程师复核 | 强调起重机行业规则、中文协议、内部知识闭环、售前软件衔接 |
| 2 | Operaide / Marbell / Mavlon | 从规格直接推进到配置和价格，闭环更长 | 坚持“不做最终报价”，把输出做成售前软件需求参数表，降低落地阻力 |
| 3 | 国内 CPQ + 大模型厂商 | 本土化、ERP 集成、成本算价能力强，容易向上游扩展 | 抢先固化卫华配套件规则、历史报价知识、改判审核流程 |
| 4 | 通用大模型问答 | 上手快，似乎能读协议 | 用整份协议、原文高亮、出处校验、规则回归和漏报危险率对比 |
| 5 | 现有售前软件继续增强 | 内部系统有数据与流程优势 | 明确定位为其上游，不重复造报价引擎，争取接口和导入格式 |

## 6. 差异化策略

### 6.1 必须保留的差异化

1. **行业化五类判断**
   - 通用产品常给 Comply / Partial / Deviation / Question。
   - 我们面向报价部给：标配、非标、模糊、不满足、可偏离，并映射到加价点、澄清函和偏离表。

2. **规则优先，模型不能放宽**
   - LLM 只做候选标签和升级线索；
   - 标配库、参数范围、型号一致性、商务阈值由确定性规则判定；
   - 降级改判必须人工填理由并可触发组长复核。

3. **双证据链**
   - 每条结论同时指向：
     - 客户协议原文页码/偏移；
     - 内部依据：标配库、加价标准、历史报价、通知、知识条目。
   - 出处校验不过，自动降为“模糊 · 依据不足”。

4. **经验资产化**
   - 报价员每次改判生成“条款—判断—报价思路”；
   - 组长审核入库；
   - 导出 SOP；
   - 可申请固化为规则并跑回归测试。

5. **上游衔接而非替代**
   - 输出需求参数表给售前软件；
   - P1 支持导入售前软件生成的己方协议，做客户协议 vs 己方协议逐条比对；
   - 不算最终价，不推 SAP，不做自动对外发送。

6. **敏感数据治理**
   - 上传后脱敏；
   - 支持只用本地模型；
   - 审计日志与规则版本留痕。

### 6.2 不应再当作独有卖点的话术

| 不建议说 | 原因 | 改成 |
|---|---|---|
| “只有我们能读整份协议” | Tender Answer、OdysseyGPT、Operaide 均已宣传整包读取 | “我们把整份协议审查落到卫华起重机的配套件和报价规则上” |
| “只有我们有偏离表” | 合规矩阵和偏离表是条款审查类标配 | “我们的偏离表直接连接加价标准、历史报价和报价思路” |
| “只有我们有出处” | 多家竞品强调 citation / traceability | “我们做出处自动校验，失败即降级为依据不足” |
| “只有我们人工复核” | 竞品普遍强调工程师最终决定 | “我们把人工改判变成可审核、可复用、可规则化的知识资产” |

## 7. 建议答辩讲述

### 7.1 一句话定位

> 通用 AI 已经能读招标书，但卫华报价部缺的是把起重机技术协议里的非标、模糊、不满足、可偏离和商务风险，逐条落到内部标配、加价标准、历史报价和售前软件输入里的“行业审查层”。

### 7.2 三步竞争叙事

1. **和通用 CPQ 比**
   - CPQ 从己方配置出发，回答“我们能卖什么、多少钱”。
   - 我们从客户协议出发，回答“客户写了什么、哪里超出标配、哪里要澄清、哪里有风险”。

2. **和通用条款审查 AI 比**
   - 它们输出通用合规状态；
   - 我们输出报价部可执行的五类标签、加价点、澄清点、偏离表和知识条目。

3. **和现有售前软件比**
   - 售前软件负责生成配置与报价；
   - 我们负责前置读懂客户协议，并把结构化需求参数表交给它，降低漏报和重复录入。

### 7.3 演示增强点

1. 展示同一条款同时命中技术规则与商务风险，例如指定品牌 + 高违约罚则；
2. 展示 LLM 建议更宽松但规则坚持非标，并要求人工复核；
3. 展示报价员改判后，知识条目在下一份协议检索中被召回；
4. 展示导出的需求参数表字段与售前软件输入对齐；
5. 如有条件，准备一张“与 Tender Answer / OdysseyGPT / Tacton / 现有售前软件”的定位图。

## 8. 产品路线建议

### P0：赢得“可信上游审查”

- 五类标签与原文高亮；
- 每条判断双证据链；
- 确定性规则与 LLM 越权测试；
- 风险偏离表与需求参数表导出；
- 改判生成知识条目与 SOP。

### P1：补齐竞争力

- 扫描件 OCR 与非标图纸参数抽取；
- 客户协议 vs 售前软件己方协议比对；
- 澄清函草稿；
- 知识条目申请规则化、审批、版本和回归测试；
- 历史/内部通知版本管理。

### P2：建立壁垒

- 用已完成的真实历史报价建立闭卷评测集：召回率、准确率、出处正确率、漏报危险率；
- 打磨起重机配套件规则包：板材、油漆、电机、减速机、电器、吊钩、车轮、卷筒；
- 与售前软件、SAP、飞书流程打通；
- 支持私有化与本地模型；
- 按客户/行业统计高频非标点，形成报价策略资产。

## 9. 待验证问题

1. 现有售前软件是否能读取客户协议，还是只接受己方配置输入？
2. 售前软件是否已有非标识别、偏离表或需求参数导入格式？
3. 卫华历史技术协议的人工审查结果能否脱敏后做闭卷评测？
4. 报价部对五类标签，尤其是“模糊 / 可偏离”的口径是否一致？
5. 内部标配库、加价标准、历史报价的字段结构能否提供脱敏样例？
6. 比赛环境能否访问本地千问，断网演示是否稳定？
