# 报价智能体 P0 MVP 设计

## 目标

在本地跑通“协议 → 规则审阅 → 人工改判 → 知识沉淀 → 导出”的最小闭环，服务报价工程师先定位非标和商务风险，再回到原文核验。

## 交互结构

- 左侧展示脱敏后的协议原文，命中条款按五类标签着色。
- 右侧展示五类清单、风险偏离表和知识沉淀三个标签页。
- 点击清单或原文高亮打开判断详情，详情包含原文证据、依据条目、规则 ID 和人工改判表单。
- 改判理由与报价思路必填；提交后产生审计记录和知识条目草稿，组长通过后状态变为“已入库”。
- 底部提供 QuoteResult、风险偏离表、需求参数表和 SOP 导出；顶部提供飞书消息预览。

## 实现边界

- Node 内置 HTTP 服务提供 `/api/demo`、`/api/analyze`、`/api/review`、`/api/approve-knowledge` 和 `/api/export`。
- P0 使用本地确定性规则，不调用外部模型；接口返回 `rules_version`、`audit_id`、协议原文证据与依据条目。
- 当前上传入口支持文字层 TXT/Markdown 演示；PDF/DOCX 解析、OCR、真实标配库、真实加价标准、真实飞书发送留到后续集成。
- 演示数据为模拟协议，已验证姓名、手机号、合同金额入口脱敏；工程参数保留用于规则判断。

## 验证方式

- `npm test`：覆盖脱敏、五类规则、风险识别、人工改判和知识条目生成。
- HTTP 手动回归：健康检查、载入演示协议、分析、改判、组长入库和三类导出。
- 浏览器自动点测受到 Windows 本地浏览器安全状态检查中断，页面静态脚本通过 `node --check`，本地页面可由 `npm start` 访问。
