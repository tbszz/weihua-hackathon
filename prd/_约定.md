# PRD 统一约定

6 份 PRD（1 份平台底座 + 5 个作品）并行写作，都必须遵守本文件，保证最后能拼起来。
背景材料：`选题方案.md`（v0.3）、`research/卫华集团调研报告.md`、`research/glossary.md`、`research/sources.md`。

## 1. 文件与命名

| 文件 | 内容 |
|---|---|
| `prd/00-平台底座-PRD.md` | 卫华 AI 工作台底座 |
| `prd/A-招投标助手-PRD.md` | 作品 A |
| `prd/B-报价智能体-PRD.md` | 作品 B（主打） |
| `prd/C-飞书跟进助手-PRD.md` | 作品 C |
| `prd/D-起重机内容工厂-PRD.md` | 作品 D |
| `prd/E-视频生产线-PRD.md` | 作品 E |

- 平台暂名「**卫华 AI 工作台**」，英文代号 `weihua-ai`。各作品的模块代号：`bid`（A）、`quote`（B）、`follow`（C）、`studio`（D）、`video`（E），底座 `core`。
- 每个会话只写自己那一份文件（附图、样例数据放在 `prd/assets/<代号>/` 下），不要改其他 PRD、`选题方案.md` 和 `research/`。

## 2. PRD 模板（每份都按这个结构）

1. **一句话定位**：给谁、解决什么、做成什么样
2. **背景与痛点**：引用场景表原话（注明序号），以及调研里的相关事实（注明出处）
3. **用户与场景**：岗位、现在怎么做、做成后怎么做
4. **范围**：P0（两天内必须演示的完整闭环）/ P1（加分项）/ 不做（明确写出来）
5. **功能需求**：编号 `<代号>-R1`、`<代号>-R2`……，每条写清输入、处理、输出和验收标准
6. **Agent / Skill 设计**：单 Agent 写清 Skills 和 Tools；多 Agent 写清每个 Agent 的职责、输入输出 Schema、谁来兜底（确定性规则 / 人工复核）
7. **数据与接口**：数据来源、样例数据方案（内部数据一律用模拟或脱敏数据）、与底座和其他作品的接口（见第 3 节）
8. **页面与交互**：主要页面列表和关键交互，可以用 ASCII 线框
9. **演示脚本**：3–5 分钟，逐步写「操作 → 画面 → 讲解词」；最后 30 秒演示链路串联
10. **验收标准与评测**：可量化的指标，以及准备哪些测试样例
11. **复用的已有项目**：具体到仓库路径或模块，说明直接用、改造还是重写
12. **两天开发计划**：按半天拆分
13. **风险与待确认事项**：标明哪些要向主办方确认

## 3. 平台底座提供的统一能力（各作品直接引用，不要重复设计）

| 能力 | 约定 |
|---|---|
| Agent Runtime | Claude Agent SDK（Loomi 模式：主 Agent + Skills + MCP 工具 + 确定性服务）；多 Agent 作品用底座提供的编排器串联（模式参考医晓） |
| 模型 | 云端模型和本地模型可切换；涉及敏感数据的作品必须支持「只用本地模型」模式 |
| 脱敏网关 | `core.redact(text) → {masked, mapping}`，`core.restore(masked, mapping)`；客户名、人名、金额、电话、合同号默认脱敏 |
| 检索 | `core.search(query, collection, filters) → [{text, score, source:{doc, page, locator}}]`，基于 PPTSight（FTS + 向量 + 数值事实） |
| 出处 | 所有 AI 结论统一用 `Claim{text, evidence:[source], confidence}` 结构，界面上可点击查看原文 |
| 飞书 | `core.feishu`：发消息、@人、读写多维表格、读文档、群消息订阅（基于 lark-cli / 开放平台） |
| 人工复核 | `core.review(item) → pending/approved/rejected`，带审计日志（参考 XFusion-Agent 的审批与审计） |
| 文件导出 | Word、PDF、Excel、飞书文档 |
| 品牌外壳 | 统一登录、导航、主题色（暂用卫华红，待拿到 VI 后替换）、大卫小华作为助手形象 |

## 4. 作品之间串联时交换的数据

| 从 → 到 | 数据对象 | 关键字段 |
|---|---|---|
| A → B | `TenderPackage` | 招标编号、甲方、截止时间、技术协议文件、资格要求 |
| A → C | `Opportunity` | 商机名称、区域、负责人、关键节点 |
| B → C | `QuoteResult` | 报价单号、非标项清单、风险项、确认人、节点 |
| D → E | `MediaAsset` | 类型（交互页录屏 / 效果图 / 3D 模型）、产品型号、卖点文案、文件路径 |
| E → 公众号 | `Article` | 标题、正文、配图、封面 |

各作品 PRD 里只需写清自己产出和消费的对象和字段；具体 Schema 以底座 PRD 为准。

## 5. 写作要求

- 中文，直接、具体，不要空话；能写成表格的写成表格
- 每份 PRD 的 P0 必须两天内能做完并完整演示，做不完的放 P1
- 引用调研结论要带出处链接；查不到或不确定的标「待确认」
- 不要开始写代码，只写 PRD
- 写完 commit 到自己的分支
