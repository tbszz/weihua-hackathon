# 起重机内容工厂 P0 MVP 设计

## 目标

在本地完成一条可手测闭环：选择或粘贴 3800t 门机参数，得到带官方出处的结构化规格、四层拆解示意、可复算的尺寸类比、现场效果图缓存候选、带出处卖点和发布校验结果。

## 取舍

- 前端使用现有 Vite + React；服务端使用 Node 原生 HTTP，保持依赖最少。
- 3800t 结构图使用参数化 SVG 示意，明确标注“结构示意，非工程图”。
- 实景合成使用下载到 `public/demo/factory-reference.jpg` 的公开厂房照片作为演示缓存，生成接口保留替换真实模型的边界。
- 3D GLB、真实图像编辑、录屏、公众号草稿写入和真人形象暂不接入，保留状态和下一步入口。

## 数据流

1. 前端选择预置型号或粘贴文本，调用 `POST /api/parse`。
2. 服务端从官方规格库抽取字段，并为未命中或无法核对的字段标记 `pending`。
3. 前端根据规格展示拆解层级与类比卡片；类比数值由服务端代码计算。
4. 上传现场照片后调用 `POST /api/scene-compose`，返回两张演示缓存候选与卖点。
5. 调用 `POST /api/validate` 检查页面数字和卖点是否都能回指官方字段；通过后模拟写入 `MediaAsset`。

## 验收

- 3800t 预置参数能展示 3800t、166.5m、130m、107m、上下各 1900t。
- 规格拆解可用按钮或左右方向键访问 L0–L3。
- 四组类比显示公式、常数和出处。
- 场景合成明确返回 `cached_demo`，并允许选中一张候选。
- 未通过校验时交付按钮不可用；通过后显示素材 ID。
- `npm test`、`npm run build` 通过。
